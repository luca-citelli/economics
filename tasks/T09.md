## Implementazione e verifica

1. Completare README con requisiti, installazione pulita, build frontend, avvio locale, uso della CLI, salvataggi, export e troubleshooting. Chiarire il significato economico degli strumenti e i limiti D1.
2. Script `scripts/start.ps1` e `scripts/start.sh`: avvio backend con frontend compilato, bind 127.0.0.1 e un solo worker; diagnosticare dipendenze mancanti. Nessun cloud o segreto richiesto.
3. Separare comandi di sviluppo e comandi d'uso. Lockfile e configurazioni incluse; percorsi relativi al progetto, niente riferimenti alla macchina dello sviluppatore.
4. Verificare installazione in ambiente pulito sul target disponibile. Windows è target iniziale: se non disponibile per test reali, dichiararlo come verifica mancante, non come compatibilità provata.
5. Eseguire smoke test sul pacchetto/build distribuito, non soltanto sul dev server: avvio, step, tasso, automatico, pausa, salvataggio, ripresa, export.
6. Audit della matrice: ogni requisito D1 ha file/feature, prova e risultato. Confrontare con scope §2.3; nessun bottone o modulo nominale scambiato per feature funzionante.
7. Rimuovere artefatti temporanei, credenziali, dati finti e riferimenti assoluti personali dalla distribuzione; mantenere scenari di esempio e risultati utili chiaramente etichettati.
8. Documentare limiti e bug residui, prestazioni misurate, feature D2/D3, schema/checkpoint supportati. Nessuna migrazione silenziosa di salvataggi incompatibili.
9. Aggiornare piano a DONE solo quando prove richieste soddisfatte; creare riepilogo di consegna con versioni, comandi verificati e istruzioni essenziali per il proprietario.

## Criteri di uscita

- Utente può installare e aprire la webapp seguendo il README senza modificare codice.
- Uso installato senza Internet; niente chiamate a LLM o servizi esterni necessarie al motore.
- Percorso browser funziona sulla build consegnata e lo storico esportato è coerente.
- Matrice docs/ACCEPTANCE interamente verificata o blocchi espliciti che impediscono di dichiarare D1 completo.
- Benchmark 260 settimane, scenari e report T08 disponibili e riproducibili.
- Test di piattaforma riportano esattamente ciò che è stato eseguito, inclusi eventuali limiti ambientali.

## Non includere

Nessuna pubblicazione su server, repository remoto, autenticazione/multiplayer, installer desktop o feature D2/D3 implicita. Se una prova manca per un limite dell'ambiente, consegnare il lavoro pronto con il limite dichiarato, senza inventare il superamento del gate.
