# Report T06 — runner, API e checkpoint

Data: 29 settembre 2026. Package/motore **0.6.0**. Ambiente verificato: Windows, Python 3.11.9, `uv` 0.7.5. Checkpoint Git del codice: `71feb08`. Contratti in [t06_contracts.md](../technical/t06_contracts.md).

## Implementato

- Un `RunService` e un worker thread seriale proprietario di `Simulation`; stati `PAUSED/RUNNING/PAUSING/STEPPING/ERROR/TERMINATED`, `+1`, `+N`, run, pausa, velocità e massima velocità. Snapshot, agenti e storico vengono pubblicati dopo commit; comandi HTTP non eseguono step sull'event loop.
- ID comando idempotenti entro run, sequenza server, politiche programmate e validate su tutte le settimane future coinvolte, assegnazione `t+2` durante lo step, ordini BC una tantum distinti con limiti di prezzo propri. `submitted_at` resta metadato; il checksum economico esclude log runtime.
- Rotte FastAPI v1 per creazione/import, snapshot, comandi, mercati, metriche, agenti con transazioni paginate, checkpoint e CSV. WebSocket numerato con limite dei frame; il client recupera lacune via HTTP. Bind solo a `127.0.0.1` e un worker nel comando `serve`.
- Checkpoint JSON atomico e versionato: tabelle NumPy (shape/dtype ricostruiti dai contratti), ledger e registro fisico completi, contratti, RNG, politiche, contatori, storico, ordine di iterazione e log di idempotenza. Import in un nuovo run in pausa, validazione contabile/fisica e checksum. Nessuna serializzazione di lock/thread/socket.
- README e contratti aggiornati con comandi reali per API e CLI. Il core sincrono rimane utilizzabile autonomamente.

Il primo avvio di pytest senza `--basetemp` ha prodotto cinque errori di setup per accesso negato alla directory temporanea di sistema nel sandbox, mentre 120 test erano passati. La riesecuzione con basetemp dentro `runs/` ha risolto il vincolo ambientale. Non è un difetto del motore. Una deprecazione di `starlette.testclient`/`httpx` è emessa dalla dipendenza durante i test API, senza fallimenti.

Le prove 100/40+60 hanno rivelato due omissioni corrette prima della chiusura: l'ordine delle chiavi del JSON canonico cambiava l'ordine delle scritture e il contatore cumulativo dei rifiuti di credito mancava dallo stato salvato. Il replay ora include ordine e contatore e confronta l'intero checksum economico, non solo i saldi.

Una prova mirata successiva ha trovato un budget di acquisto BC ricaricato come stringa nella coda runtime. La conversione con `money()` al ripristino è stata corretta; `test_checkpoint_keeps_pending_policy_and_command_id` è stato rieseguito con budget monetario pendente e ha passato (exit code 0). Ruff resta verde.

## Limiti e prossimo passo

T06 verifica backend e runner senza un frontend browser completo; il percorso visivo resta T07. Il throughput e la memoria su 1.000/260 e 10.000/52 settimane vanno misurati in T08; lo scheduler espone velocità effettiva, ma non promette il target in ogni scenario. La CLI `run` è sincrona e autonoma, mentre pausa/ripresa interattiva usa l'API. Gli endpoint `agent` coprono persone, imprese e banche; le istituzioni sono leggibili tramite metriche e ledger/checkpoint. Solo il bind locale è supportato nel D1. D1 resta incompleto.
